## 0. 한 줄

> **2D 그림 여러 장을 읽어 와, 각각을 애니메이션 툴로 편하게 움직이고, 애니메이션 그래프의 곡선을 고쳐 타이밍을 잡는다.**

목적(소유자, 2026-11-11): 애프터 이펙트 · 마야 같은 도구의 결과물은 **렌더된 동영상으로만** 유니티에 들어갈 수 있었다. 이것을 푼다 —
이 툴에서 여러 전환 세트를 만들면, **유니티에서 불러오기만 해도 UI 오브젝트들이 생성되어 의도한 대로 움직인다.**

화면을 덮고 걷는 전환은 그 쓰임의 하나다. 깊이 · 리그 구조 · 카메라는 몰라도 된다.

### 이 작업을 어디에 쓰나 (소유자, 2026-11-11)

- **무엇을 만드나**: 유니티 UI를 써서 **화면 전환(ScreenTransition) · UI 컷인(CutIn)** 같은 연출을 편하게 만든다. 만드는 사람은 툴의 뷰포트에서 "perspectiveView 느낌으로"(소유자의 말) 보면서 짓는다.
- **유니티 쪽에 바라는 것은 적다**: 이 툴은 특정 유니티 환경을 크게 요구하지 않는다. 유니티 쪽은 기본 UGUI(`RectTransform` · `Image` · `CanvasGroup`)만으로 서야 하고, 특정 프로젝트 구조 · 패키지 · 렌더 파이프라인 · 셰이더 · 런타임 저장소에 기대지 않는다(§2의 11과 같은 잣대).
- **지금까지 지은 것이 쓰이는 자리**:
  - 전환 = 층들 + 타임라인 하나 → 유니티에서 층 하나가 UI 오브젝트 하나(`RectTransform` + 그림 또는 색 + 불투명도)가 되고, 타임라인이 그 오브젝트들을 움직인다.
  - `ScreenTransition.Core`(netstandard2.1 · C# 9 · 엔진 참조 없음) → 유니티 쪽 재생기가 그대로 써서, 툴에서 본 모습과 같게 움직인다.
  - 이벤트 키 → 게임이 받는 신호(예: 전환의 `covered` · `release`).
  - 저작 파일(`*.transition-authoring.json`) → 산출물(보류)의 원본.
- **컷인도 같은 모델로 만든다**: 화면을 다 덮지 않는 연출도 층들 + 타임라인이다 — 모델을 "덮는 전환"에 좁혀 굳히지 않는다(T2의 원칙).

## 3. 모델 — 전환 하나

지금 코드(출발점)에는 세 층의 개념이 겹쳐 있다: 세트(`RigAsset`) + 애니메이션 셋(`x_in` · `x_hold` · `x_out`) + 연출(`EmojiAsset`의 `Screen`). 쓰는 사람에게는 하나여야 한다.

**전환 = 층들 + 타임라인 하나 + 표지 둘.**

| 무엇 | 뜻 | 지금 코드의 무엇에서 오는가 |
|---|---|---|
| **전환** | 이름 · 층들 · 타임라인 · 표지 | 세트 + 그 연출을 하나로 합친다 |
| **층** | 그림 또는 색 사각형 하나. 위아래로 쌓인다(뒤의 것이 위). 화면의 어디에 붙고(§4) 어떻게 늘어나는가 | `RigNodeAsset`(그림 · 색). 부모·자식은 "묶기"로만 남긴다 |
| **타임라인** | 전환에 하나. 층마다 자리 · 회전 · 배율 · 불투명도의 키 | 지금의 애니메이션(커브 · 그래프 · 도프 시트) 그대로 |
| **표지 "덮였다"** | 화면이 다 덮인 프레임 — 게임이 여기서 장면을 바꾼다 | 지금의 이벤트 키 `covered` |
| **표지 "걷기 시작"** | 덮인 채 머무는 구간의 끝. "덮였다" ~ "걷기 시작"이 **머묾**이고 게임이 준비될 때까지 되풀이한다 | 지금의 머묾 애니메이션(`x_hold`) |

- **저작은 한 타임라인으로 한다**(그래프를 잡기에는 하나가 편하다). 내보낼 때 표지에서 셋으로 자른다: 덮기(0 ~ 덮였다) · 머묾(덮였다 ~ 걷기 시작, 되풀이) · 걷기(걷기 시작 ~ 끝).
- **머묾은 처음과 끝의 모습이 같아야 이어진다** — 툴이 두 표지에서의 모습을 맞대어 보이고, 어긋나면 알린다. 머묾이 없어도 된다(두 표지가 같은 프레임 = 덮이자마자 걷힌다).
- 키는 **그 프레임의 모습**이다. 출발점의 "상대값/절대값 · 유지/복원" 고르기는 캐릭터에 얹던 때의 개념이라 걷었다 — 키는 **가만히 선 자세(배치)에 대한 값**이고 끝에서 마지막 키가 남는다(T2-3, 2026-11-11. 처음 안은 "절대값 · 유지로 고정"이었다 — 아래 T2-3의 까닭).
- 표지를 옮기면 잘리는 자리만 바뀐다 — 키는 그대로다.

## 4. 화면 비율 — 어디서나 덮인다

층은 **기준 화면(1920×1080)**에서 짓는다. 실제 화면이 다르면 층마다 두 값으로 자리를 다시 잡는다.

- **붙는 자리**(`ScreenAnchor`): 가운데 · 왼쪽 · 오른쪽 · 위 · 아래 · 네 모서리. 그 자리에서의 거리를 지킨다 — "왼쪽 끝에 붙은 기둥"은 더 넓은 화면에서도 왼쪽 끝에 붙는다.
- **늘어나기**(`ScreenFit`): 그대로 / **늘이기**(가로·세로 따로 — 화면 전체 바탕) / **덮기**(비율을 지키고 넘치게 — 그림이 안 찌그러진다).

방향 코드였던 `ScreenLayout`(`Place` — 순수 함수)과 그 테스트는 2026-11-11에 걷었다(쓰지 않는 코드 — 구조 #5). T3′을 열 때 히스토리(`fc1818e` 이전)에서 꺼내거나 새로 짓는다.

할 일:
- 층(`RigNodeAsset`)에 `Anchor` · `Fit`을 더한다. 층 표 가져오기가 고르는 기본값: 화면 전체짜리 층 = 가운데 · 덮기, 한쪽 끝에 닿은 층 = 그 끝, 나머지 = 가운데.
- **여러 비율로 미리보기**: 재생 줄에 화면 비율 고르기(16:9 · 21:9 · 4:3 · 9:16 · 직접). 뷰포트의 무대가 그 크기가 되고 층이 `ScreenLayout.Place`로 선다.
- **움직임의 거리도 화면을 따른다**: "화면 밖에서 들어온다"(`SlideFromOutside`)가 고정 픽셀이 아니라 "그 화면의 밖"이어야 한다 — 넓은 화면에서 덜 나간 채 시작하면 안 된다.
  안: 키 값을 "기준 화면에서의 px"로 두고, 재생할 때 그 층의 붙는 자리 쪽 축만 화면이 늘어난 만큼 늘린다. **이 규칙은 T3에서 정하고 테스트로 못 박는다**(열린 것 §8의 1).

## 5. 덮임 검사 — "다 덮였다"를 툴이 확인한다

전환의 약속은 "다 덮인 순간 게임이 장면을 바꾼다"이다. 지금은 눈으로 본다.

- "덮였다" 표지의 프레임에서, **불투명한 층들이 화면을 빈틈없이 덮는지** 센다. 안 덮인 곳이 있으면 뷰포트에 빨갛게 칠하고 문제 목록에 올린다(막는 문제 — 내보내기가 안 된다).
- **머묾 구간 내내** 덮여 있어야 한다 — 표지 프레임만이 아니라 머묾의 프레임들을 훑는다.
- **미리보기에서 고른 비율들 전부**에서 센다(§4). 16:9에서 덮여도 21:9에서 비면 알린다.
- 불투명 = 불투명도가 1이고, 색 사각형이거나 그림이 빈틈없는 층. 그림에 투명한 곳이 있는지는 PNG의 알파를 읽어 "빈틈없는 사각형"만 친다(가장자리가 삐죽한 그림은 덮는 것으로 안 친다 — 보수적으로).

방향 코드였던 `CoverCheck`(`Check` — 볼록 사각형들로 화면을 덮는지)와 그 테스트는 2026-11-11에 걷었다(구조 #5). T4를 열 때 히스토리(`fc1818e` 이전)에서 꺼내거나 새로 짓는다.

## 6. 산출물 — 오브젝트와 트랙, 카메라와 깊이 없이

`ked-motion-tool-extend`의 컷 파일(`cut/1`)과 **뼈대가 닮았다**: 오브젝트 목록 + 수의 트랙 + 그림 트랙, 시각은 프레임, 다 구운 한 덩어리. **키를 적는 방식은 똑같다**(§2의 7 — `f` · `v` · `i` · `o`, 그림은 계단 키): 나중에 읽는 부분을 합칠 길을 남긴다. 그 밖은 이 저장소가 정한다.

아래는 T5의 출발점이다 — 틀 · 단위 · 가림 · 매개변수(§10)가 들어오며 자란다.

```
{
  "format": "transition/1",
  "name": "station",
  "frames": 74, "fps": 24,
  "stage": { "width": 1920, "height": 1080 },      // 기준 화면
  "covered": 6,                                    // 덮였다 — 게임이 여기서 장면을 바꾼다
  "release": 54,                                   // 걷기 시작 — covered ~ release가 머묾(되풀이). 같으면 머묾이 없다
  "objects": [
    { "id": "Backdrop", "parent": "", "x": 0, "y": 0, "width": 1920, "height": 1080,
      "color": "#10262B", "anchor": "center", "fit": "stretch" },
    { "id": "pillars_left", "parent": "", ..., "image": "art/03_pillars_left.png", "anchor": "left", "fit": "none" }
  ],
  "tracks": [ { "target": "pillars_left", "what": "x", "keys": [ { "f": 0, "v": -820, "i": 0, "o": 0 }, ... ] } ],
  "images": [],
  "events": []
}
```

컷 파일과 다른 것: `camera`가 없다 · 오브젝트에 `depth`가 없다 · `covered` · `release`가 있다 · 오브젝트에 `anchor` · `fit`이 있다.

- 읽어서 그 프레임의 모습을 내는 계산(**기준 재생기**)은 `ScreenTransition.Core`에 순수 C#으로 둔다 — 게임(UGUI)이 그대로 쓰고, 툴의 미리보기도 그것을 쓴다. `TransitionFileDto` · `TransitionPlayer`(틀에 맞춤 + 표지).
- 툴의 미리보기와 기준 재생기가 같은 모습을 내는지 **프레임마다 맞추는 테스트**를 둔다.
- **형식 문서**와 **기준 프레임 표**(어떤 프레임에 어떤 층이 어디에 어떤 모습인가)를 함께 낸다 — 다른 엔진이 그 표에 맞춰 스스로 잰다(§10.1).
- 옛 산출물(`rigs.json` · `motions.json` · `emojis.json`)은 이미 걷었다(T1-4d).

T2-4 ①에서 정한 것:
- 세트가 타임라인을 든다(`RigAsset.Timeline`). 타임라인의 이름 · 세트는 주인 세트의 것이다(따로 적지 않는다). 세트를 지우면 타임라인도 함께 간다. 저작 파일 `motion-authoring/4`.
- 세트 이름 = 타임라인 이름이라 코어의 이름 규칙(`[a-z0-9_]+`)을 따른다 — 세트 이름은 영문 **소문자**로 시작하는 소문자 · 숫자 · `_`다.
- 화면: 왼쪽의 모션 목록이 사라졌다. 세트를 고르면 그 타임라인이 묶인다. **배치 모드는 "모션을 안 고른 상태"가 아니라 세트 칸의 "배치" 토글이다**(새 세트는 켜진 채 열린다). 오른쪽 "모션" 탭은 "타임라인" 탭(이름 칸은 없다 — 세트의 이름 칸). 세트를 고르면 보기는 무대 전체다(전에는 세트에 맞췄다).
- 예시 빌더: 등장 · 머묾 · 퇴장을 그 세트의 사본에서 짓고 본 세트의 타임라인으로 잇는다. 예시의 모습은 화소까지 같다.

- **가 — 구조부터(권고).** ① 타임라인을 세트 안으로(모션 목록 · 모션 추가/지우기/이름 바꾸기가 사라지고 세트를 고르면 그 타임라인) ② 이름(세트+타임라인 → 전환, 노드 → 층, 문서 · 편집기 · 화면 · 파일 확장자). 테스트 발판을 함께 다시 짓는다.

## 8. 열려 있는 것

1. **움직임의 거리와 화면 비율**(§4의 끝 — **T3′의 '움직임의 단위'(px / 틀 비율)로 푼다**, §2의 8). "왼쪽에서 들어온다"의 −820px이 21:9에서 얼마가 되어야 하는가. 층의 붙는 자리로 풀리는 것(끝에 붙은 층은 그 끝과 함께 움직인다)과 안 풀리는 것(가운데 붙은 층이 화면 밖에서 온다)을 갈라 T3에서 정한다.
2. **머묾이 이어지는지를 어디까지 보나.** 자리·배율·회전·불투명도가 두 표지에서 같으면 된다 — 그림이 프레임마다 바뀌는 층(장 넘기기)은 한 바퀴가 머묾의 길이와 맞아야 한다.
3. **그림의 빈틈**(§5). PNG의 알파를 읽는 값 — 큰 그림이 많으면 느리다. 한 번 읽어 "빈틈없는 사각형인가"만 적어 둔다.
4. **게임 쪽의 약속.** 게임이 전환을 부르는 길(이름으로) · 머묾을 끝내는 신호 · `covered`를 듣는 길. `ked-presentation-runtime`과는 무관하다 —
   유니티에서 산출물을 읽어 UI 오브젝트를 세우는 코드는 **이 툴의 것**(이 툴의 산출물)이고, 뒤의 일이다(보류). 런타임 저장소에 넣지 않는다.

## 9. 하지 않는 것

- 카메라 · 깊이 · 캐릭터 · 씬 · 클립 · 이모지.
- 조립(세트가 세트를 품는다) — 범용성은 되풀이와 매개변수로 얻는다.
- 틀 안의 틀 · 자동 배치(UI 레이아웃 도구가 된다).
- 글의 모양(글꼴 · 줄바꿈 · 넘침 처리) — 게임의 것이다. 툴은 글이 설 상자와 움직임만 안다.
- 소리.
- 특수한 셰이더가 있어야 되는 것(부드러운 가장자리 가림 · 밝기 무늬 닦기) — 뒤로 미룬다.

## 10. 범용화 — UI 수준으로 (2026-11-10 — 소유자가 굳혔다)

> **보류(2026-11-11 오후)** — 소유자가 의도와 목적을 확정한 뒤에 연다. 아래 결정은 기록으로 그대로 둔다.

소유자의 방향: 이 툴을 "이 게임의 화면 전환 다섯 개"가 아니라 **어느 화면 · 어느 영역 · 어느 게임에서도 쓰는 전환**을 만드는 도구로. 정해진 것은 §2의 6~13이고, 여기는 그 뜻과 단계다.

### 10.1 "범용"이 뜻하는 것 — 다섯 축

| 축 | 지금 | 범용이면 |
|---|---|---|
| **어디에 서는가** | 화면 전체(1920×1080 기준) | **틀**(frame) — 화면 전체일 수도, 패널 · 팝업 · 카드 하나의 사각형일 수도 있다. 전환은 "이 틀을 덮고 걷는다". 화면 전체는 틀의 한 경우다 |
| **크기가 달라도** | 붙는 자리 + 늘어나기(§4 — 아직 코드뿐) | 층마다 **붙는 자리 · 늘어나기 · 단위**. 움직임의 거리도 px이 아니라 **틀에 대한 비율**로 적을 수 있다("틀 너비만큼 왼쪽에서"). 안전 영역(노치)도 틀의 한 종류 |
| **무엇으로 그리는가** | 그림 · 색 사각형 | + 그라데이션 · 둥근 사각형/원 · 9조각 늘이기 · **가림(마스크)** — 닦기 · 조리개 · 블라인드는 가림 없이는 못 만든다. + **되풀이**(같은 조각을 격자 · 줄로 놓고 시차를 준다 — 타일 · 줄무늬) |
| **무엇이 움직이는가** | 자리 · 회전 · 배율 · 불투명도 | + 색 · 크기(너비/높이) · 가림의 진행도 · 그라데이션의 자리 |
| **쓰는 쪽이 바꾸는 것** | 없다(구운 한 덩어리) | **매개변수** — 색 · 그림 · (글)을 이름 붙은 자리로 내어 놓고 게임이 갈아 끼운다. 방향 뒤집기(왼→오 ⇄ 오→왼), 빠르기, 거꾸로 틀기(걷기 = 덮기의 역재생) |

그리고 축이 아닌 바탕 하나: **런타임과의 약속이 엔진에 묶이지 않는다.** 산출물(`transition/1`)의 뜻을 문서로 적고, 순수 C# 기준 재생기(`ScreenTransition.Core`)와 **기준 프레임**(어떤 프레임에 어떤 층이 어디에 어떤 모습인가를 적은 표)을 함께 낸다 — 다른 엔진 · 다른 UI 체계가 그 표에 맞춰 구현하고 맞는지 스스로 잰다.

### 10.2 지키는 것

- **몰라도 되는 것은 그대로 몰라도 된다.** 범용이 되어도 "층을 쌓아 덮고 걷는다"가 첫 화면이다. 틀 · 단위 · 매개변수는 기본값이 "화면 전체 · px · 없음"이라 안 건드리면 지금과 같다.
- **조립은 여전히 없다**(§2의 4). 범용성은 세트가 세트를 품는 것으로 얻지 않는다 — 되풀이(같은 조각 여럿)와 매개변수(같은 전환을 다르게)로 얻는다.
- **카메라 · 깊이 · 캐릭터는 여전히 없다.**
- **툴의 미리보기 = 기준 재생기**(같은 계산, 프레임마다 맞추는 테스트). 기능을 더할 때마다 기준 재생기와 기준 프레임이 먼저다.
- **기준은 UGUI 하나, 잣대는 "특수한 셰이더 없이 되는 것"**(§2의 11). 기능을 받을지 말지를 이것으로 가른다.
- **덮임 검사는 "덮는 전환"일 때만 막는다.** 틀의 일부만 지나가는 전환(장식 · 강조)은 덮였다 표지가 없어도 된다.

### 10.3 단계 — T와 어떻게 이어지나

T1(걷어 내기)과 T2(전환 하나로)는 그대로 간다 — 범용화의 바탕이다. T3부터 범용의 뜻을 담아 넓힌다.

| 단계 | 내용 | 끝나면 |
|---|---|---|
| T1-4 · T1-5 | 씬 · 카메라 · 깊이 · 캐릭터 리그, 코어 사본 줄이기 | 툴이 세트와 연출만 안다 |
| T2 | 전환 하나로 합친다(§3) | "세트 · 연출 · 모션 셋"이 화면에서 사라진다 |
| **T3′ 틀과 배치** | §4를 넓힌다: 화면 → **틀**. 층의 붙는 자리 · 늘어나기, **움직임의 단위**(px / 틀 비율 — §8의 1이 이것으로 풀린다), 여러 틀 크기로 미리보기(화면 비율들 + 직접 적은 사각형) | 예시 다섯이 21:9 · 4:3 · 세로에서도, 작은 패널 안에서도 선다 |
| T4 | 덮임 검사(§5) — 틀에 대해. 덮는 전환일 때만 막는다 | "덮였다"를 눈으로 안 본다 |
| **T5′ 산출물과 약속** | `transition/1` + 기준 재생기 + **형식 문서 · 기준 프레임 내보내기**. 재생의 상태(덮는 중 › 머묾 › 걷는 중, 건너뛰기 · 도중에 끊기)를 약속에 적는다 | 엔진이 달라도 같은 전환이 돈다 |
| **G2 가림** | ① 기울지 않은 사각형 가림 + 진행도 트랙(닦기 · 블라인드 — UGUI에서 가볍다) ② 그림 가림(알파) · 기운 가림 | "닦기류"가 틀 하나로 된다 |
| **G4 매개변수** | 먼저 색을 층의 값으로(색 트랙 — G1에서 당겨 온 조각). 색 · 그림 자리에 이름을 붙여 내어 놓는다, 방향 뒤집기 · 빠르기 · 거꾸로 틀기. 미리보기에서 값을 바꿔 본다 | 전환 하나가 여러 화면 · 여러 색으로 쓰인다 |
| **G1 그리는 것** | 크기의 트랙, 그라데이션, 둥근 사각형/원, 9조각 | 그림 없이 도형만으로 전환을 짓는다 |
| **G3 되풀이** | 한 조각을 격자 · 줄 · 원으로 놓고 시차(순서: 차례 · 가운데부터 · 무작위)를 준다. 저작은 조각 하나, 산출물은 펼친 층들 | 타일 · 줄무늬가 조각 하나의 키로 된다 |
| **G5 글** | 글 층 — 설 상자와 움직임만. 내용은 매개변수. 넘침은 게임의 규칙(형식 문서에 적는다). 글은 덮임 검사에 치지 않는다 | 장 제목 · 날짜 소개가 전환에 낀다 |
| T6 | 전환 틀(닦기 · 좌우에서 닫기 · 조각이 차례로 · 조리개…) — 매개변수 달린 시작점으로. 문서를 이 툴의 것으로 | 빈 문서에서 5분 안에 쓸 만한 전환이 나온다 |

순서의 까닭: 틀과 약속(T3′ · T5′)이 먼저여야 뒤의 것들이 "어느 크기에서나 · 어느 엔진에서나"로 처음부터 지어진다. 가림과 매개변수가 "범용"의 값을 가장 많이 낸다 — 가림이 있어야 닦기류가 되고, 매개변수가 있어야 전환 하나를 여러 곳에 쓴다. 가림은 재생하는 쪽에 가장 큰 일을 시키므로 T5′의 약속에 자리를 미리 비워 둔다.

### 10.4 왜 이렇게 정했나

물음 여섯과 순서 하나에 받은 의견을 소유자가 그대로 굳혔다(§2의 7~13). 근거만 남긴다.

| 정한 것 | 근거 |
|---|---|
| 컷 파일과는 키 규약만 같게 | 틀 · 단위 · 가림 · 매개변수가 들어가면 재생기가 하는 일이 달라진다 — 코드를 같게 묶으면 양쪽이 서로를 막는다. 키 규약만 같으면 읽는 부분을 합칠 길은 남는다 |
| 틀까지, 전환당 하나 | "왼쪽에서 들어온다"의 거리가 px에서 틀 비율로 바뀌는 것은 키 값의 뜻이 바뀌는 일이라, 나중에 넣으면 만든 전환을 다 고쳐야 한다. 중첩 · 자동 배치까지 가면 UI 레이아웃 도구가 된다 |
| 글은 맨 뒤, 자리와 움직임만 | 툴은 글의 실제 크기를 모른다 — 겹침 · 넘침을 확인해 줄 수 없다. 상자까지만 약속한다 |
| 가림은 기울지 않은 사각형부터 | UGUI에서 기울지 않은 사각형 가림은 가볍고, 기운 사각형 · 그림 가림은 훨씬 무겁다. 닦기 · 블라인드는 대부분 앞의 것으로 된다 |
| 기준은 UGUI 하나 | 두 번째 런타임은 지금 만들어도 맞는지 확인할 곳이 없다. 기준 프레임 표가 있으면 나중에 스스로 잴 수 있다 |
| 이름은 T2에서, 옛 산출물은 T5에서 | 모델이 바뀔 때 이름도 함께 바꿔야 같은 코드를 두 번 뒤집지 않는다. 새 산출물이 서기 전에 옛 것을 걷으면 내보낼 길이 끊긴다 |
| 가림 · 매개변수 먼저 | "범용"의 값을 가장 많이 낸다 |
