# 화면 전환 저작 도구 — 계획

이 저장소는 **화면 전환만** 만드는 도구다. 소유자 결정(2026-11-10). 이 문서가 이 저장소의 첫 계획서이고, 여기서 일을 이어받는 사람(세션)은 이것부터 읽는다.

## 0. 한 줄

> 깊이도 리그 구조도 카메라도 몰라도, **층을 쌓아 화면을 덮고 걷는 전환**을 편하게 만든다. 어느 화면 비율에서도 빈틈없이 덮이고, "다 덮였다"를 툴이 확인해 준다.

## 1. 어디서 왔고, 세 갈래 중 무엇인가

한 저장소(`ked-motion-tool-extend`)에서 자라던 것을 "누가 형태를 정하는가 · 쓰는 사람이 무엇을 알아야 하는가"로 셋으로 갈랐다.

| | characterRig | **screenTransition(여기)** | extend |
|---|---|---|---|
| 만드는 것 | 캐릭터 모션 · 이모지 | **화면을 덮는 전환** | 컷(씬 + 카메라 + 타임라인) |
| 형태를 정하는 쪽 | 유니티(스키마를 따른다) | 툴 | 툴 |
| 쓰는 사람이 알아야 할 것 | 리그 구조 · 컨트롤러 | **거의 없다 — 층과 화면** | 깊이 · 카메라 · 계층 |
| 카메라 · 깊이 | 있다 | **없다** | 있다 |
| 출발 커밋 | `d37c678` | **`a522149`** | 계속 |

`main`은 `a522149` 그대로다(`ked-motion-tool-extend`에서 클립을 걷어 내기 직전). 이 계획서와 방향 코드는 `dev`에 있다.

**이 출발점을 고른 까닭**: 그 시점의 툴이 사실상 화면 전환 툴이었다 — 층 표 가져오기, 시차, "화면 밖에서 들어온다", "제 차례 전까지 숨기기", 등장 › 머묾 › 퇴장을 이어 보기,
예시 다섯 장면(`examples/transitions/` — station · pillar · lapis · heredity · mercury). 새로 짓지 않는다. **거기서 화면 전환에 필요 없는 것을 걷어 내고, 없던 둘(화면 비율 · 덮임 검사)을 더한다.**

## 2. 정해진 것 (소유자, 2026-11-10)

1. **카메라와 깊이는 없다.** 쓰는 사람이 리그 구조·깊이를 몰라도 된다.
2. **화면 비율이 달라도 덮인다.** 1920×1080 하나만이 아니다(§4).
3. **덮인 채 기다리는 구간(머묾)이 있다.** 덮는다 › (덮인 채 머문다 — 되풀이) › 걷힌다(§3).
4. **조립은 뺀다.** 세트가 세트를 품는 것 · 재생 블록 · 새 세트로 빼기 · 안쪽 고치기 — 전환 하나에는 과하고 헷갈렸다.
5. **산출물은 컷 파일과 같은 계열**(오브젝트 + 트랙)이되 **카메라와 깊이가 없다**(§6) — 게임의 재생 코드가 한 벌이면 되게.

작업 관습은 `CLAUDE.md`.

## 3. 모델 — 전환 하나

지금 코드(출발점)에는 세 층의 개념이 겹쳐 있다: 세트(`RigAsset`) + 애니메이션 셋(`x_in` · `x_hold` · `x_out`) + 연출(`EmojiAsset`의 `Screen`). 쓰는 사람에게는 하나여야 한다.

**전환 = 층들 + 타임라인 하나 + 표지 둘.**

| 무엇 | 뜻 | 지금 코드의 무엇에서 오는가 |
|---|---|---|
| **전환** | 이름 · 층들 · 타임라인 · 표지 | 세트 + 그 연출을 하나로 합친다 |
| **층** | 그림 또는 색 사각형 하나. 위아래로 쌓인다(뒤의 것이 위). 화면의 어디에 붙고(§4) 어떻게 늘어나는가 | `RigNodeAsset`(그림 · 색). 부모·자식은 "묶기"로만 남긴다 |
| **타임라인** | 전환에 하나. 층마다 자리 · 회전 · 배율 · 불투명도의 키 | 지금의 애니메이션(커브 · 그래프 · 도프 시트) 그대로 |
| **표지 "덮였다"** | 화면이 다 덮인 프레임 — 게임이 여기서 장면을 바꾼다 | 지금의 이벤트 키 `covered` |
| **표지 "걷기 시작"** | 덮인 채 머무는 구간의 끝. "덮였다" ~ "걷기 시작"이 **머묾**이고 게임이 준비될 때까지 되풀이한다 | 지금의 머묾 애니메이션(`x_hold`) |

- **저작은 한 타임라인으로 한다**(그래프를 잡기에는 하나가 편하다). 내보낼 때 표지에서 셋으로 자른다: 덮기(0 ~ 덮였다) · 머묾(덮였다 ~ 걷기 시작, 되풀이) · 걷기(걷기 시작 ~ 끝).
- **머묾은 처음과 끝의 모습이 같아야 이어진다** — 툴이 두 표지에서의 모습을 맞대어 보이고, 어긋나면 알린다. 머묾이 없어도 된다(두 표지가 같은 프레임 = 덮이자마자 걷힌다).
- 키는 **그 프레임의 모습**이다. 출발점의 "상대값/절대값 · 유지/복원"은 캐릭터에 얹던 때의 개념이라 전환에서는 숨긴다(안에서는 절대값 · 유지로 고정).
- 표지를 옮기면 잘리는 자리만 바뀐다 — 키는 그대로다.

## 4. 화면 비율 — 어디서나 덮인다

층은 **기준 화면(1920×1080)**에서 짓는다. 실제 화면이 다르면 층마다 두 값으로 자리를 다시 잡는다.

- **붙는 자리**(`ScreenAnchor`): 가운데 · 왼쪽 · 오른쪽 · 위 · 아래 · 네 모서리. 그 자리에서의 거리를 지킨다 — "왼쪽 끝에 붙은 기둥"은 더 넓은 화면에서도 왼쪽 끝에 붙는다.
- **늘어나기**(`ScreenFit`): 그대로 / **늘이기**(가로·세로 따로 — 화면 전체 바탕) / **덮기**(비율을 지키고 넘치게 — 그림이 안 찌그러진다).

방향 코드: `src/Mt.Authoring/Transition/ScreenLayout.cs`(`Place` — 순수 함수. 게임의 재생기와 한 벌이어야 한다) · 테스트 `TransitionDirectionTests`.

할 일:
- 층(`RigNodeAsset`)에 `Anchor` · `Fit`을 더한다. 층 표 가져오기가 고르는 기본값: 화면 전체짜리 층 = 가운데 · 덮기, 한쪽 끝에 닿은 층 = 그 끝, 나머지 = 가운데.
- **여러 비율로 미리보기**: 재생 줄에 화면 비율 고르기(16:9 · 21:9 · 4:3 · 9:16 · 직접). 뷰포트의 무대가 그 크기가 되고 층이 `ScreenLayout.Place`로 선다.
- **움직임의 거리도 화면을 따른다**: "화면 밖에서 들어온다"(`SlideFromOutside`)가 고정 픽셀이 아니라 "그 화면의 밖"이어야 한다 — 넓은 화면에서 덜 나간 채 시작하면 안 된다.
  안: 키 값을 "기준 화면에서의 px"로 두고, 재생할 때 그 층의 붙는 자리 쪽 축만 화면이 늘어난 만큼 늘린다. **이 규칙은 T3에서 정하고 테스트로 못 박는다**(열린 것 §8의 1).

## 5. 덮임 검사 — "다 덮였다"를 툴이 확인한다

전환의 약속은 "다 덮인 순간 게임이 장면을 바꾼다"이다. 지금은 눈으로 본다.

- "덮였다" 표지의 프레임에서, **불투명한 층들이 화면을 빈틈없이 덮는지** 센다. 안 덮인 곳이 있으면 뷰포트에 빨갛게 칠하고 문제 목록에 올린다(막는 문제 — 내보내기가 안 된다).
- **머묾 구간 내내** 덮여 있어야 한다 — 표지 프레임만이 아니라 머묾의 프레임들을 훑는다.
- **미리보기에서 고른 비율들 전부**에서 센다(§4). 16:9에서 덮여도 21:9에서 비면 알린다.
- 불투명 = 불투명도가 1이고, 색 사각형이거나 그림이 빈틈없는 층. 그림에 투명한 곳이 있는지는 PNG의 알파를 읽어 "빈틈없는 사각형"만 친다(가장자리가 삐죽한 그림은 덮는 것으로 안 친다 — 보수적으로).

방향 코드: `src/Mt.Authoring/Transition/CoverCheck.cs`(`Check` — 볼록 사각형들로 화면을 덮는지, 안 덮인 칸들을 돌려준다. 덮였다고 잘못 말하지 않는다) · 테스트 `TransitionDirectionTests`.

## 6. 산출물 — 컷 파일과 같은 계열, 카메라와 깊이 없이

`ked-motion-tool-extend`가 정한 컷 파일(`cut/1` — 그 저장소의 `docs/PLAN-standalone.md` §7, 코드 `src/Ked.Presentation.Core/Cut/`)과 **같은 뼈대**를 쓴다: 오브젝트 목록 + 수의 트랙 + 그림 트랙, 시각은 프레임, 다 구운 한 덩어리.

```
{
  "format": "transition/1",
  "name": "station",
  "frames": 74, "fps": 24,
  "stage": { "width": 1920, "height": 1080 },      // 기준 화면
  "covered": 6,                                    // 덮였다 — 게임이 여기서 장면을 바꾼다
  "release": 54,                                   // 걷기 시작 — covered ~ release가 머묾(되풀이). 같으면 머묾이 없다
  "objects": [
    { "id": "Backdrop", "parent": "", "x": 0, "y": 0, "width": 1920, "height": 1080,
      "color": "#10262B", "anchor": "center", "fit": "stretch" },
    { "id": "pillars_left", "parent": "", ..., "image": "art/03_pillars_left.png", "anchor": "left", "fit": "none" }
  ],
  "tracks": [ { "target": "pillars_left", "what": "x", "keys": [ { "f": 0, "v": -820, "i": 0, "o": 0 }, ... ] } ],
  "images": [],
  "events": []
}
```

컷 파일과 다른 것: `camera`가 없다 · 오브젝트에 `depth`가 없다 · `covered` · `release`가 있다 · 오브젝트에 `anchor` · `fit`이 있다.

- 읽어서 그 프레임의 모습을 내는 계산은 `Ked.Presentation.Core`에 둔다(순수 C# — 게임이 그대로 쓴다). `extend`의 `CutPlayer`와 **트랙을 읽는 부분은 같은 코드여야 한다**.
  이 저장소의 Core 사본에는 아직 `Cut/`이 없다(출발점이 그보다 앞이다) — T5에서 `extend`의 `Cut/` 폴더를 가져오고, 그 위에 전환의 것(`TransitionFileDto` · `TransitionPlayer`: 화면 비율 맞춤 + 표지)을 얹는다.
- 툴의 미리보기와 게임의 재생이 같은 모습을 내는지 **프레임마다 맞추는 테스트**를 둔다(`extend`의 `CutTests.툴의_미리보기와_코어의_컷_재생이_모든_프레임에서_같은_모습을_낸다`가 본이다).
- 옛 산출물(`rigs.json` · `motions.json` · `emojis.json`)은 이 저장소에서 더는 내지 않는다(T5에서 걷어 낸다).

## 7. 순서

각 단계는 전체 테스트가 통과한 채로 끝낸다. 걷어 내는 단계는 "안 쓰는 기능은 흔적 없이"(코드 · 주석 · 문서 · 테스트까지).

| 단계 | 내용 | 끝나면 |
|---|---|---|
| T0 | 출발점 · 이 계획서 · 방향 코드 | **끝** |
| **T1** | **걷어 낸다 — 화면 전환에 필요 없는 것.** 아래 "걷어 낼 것" 표. 예시 다섯은 남는다 | 툴이 세트와 화면 연출만 안다 |
| **T2** | **전환 하나로 합친다**(§3) — 세트 + 애니메이션 셋 + 연출 → 전환(층들 + 타임라인 하나 + 표지 둘). 왼쪽 목록이 "전환", 하이어아키가 "층". 예시 다섯을 한 타임라인으로 옮긴다 | "세트 · 연출 · 등장/머묾/퇴장 모션"이라는 말이 화면에서 사라진다 |

| **T4** | **덮임 검사**(§5) — 표지 프레임과 머묾 구간, 고른 비율 전부. 뷰포트에 안 덮인 곳, 문제 목록 | "덮였다"를 눈으로 안 본다 |

| 예시 다섯과 그 그림 · 그림 생성기 | `examples/transitions` · `tools/make-transition-art.py` |
| 화면 캡처(`MT_RENDER_DIR`) | `tests/Mt.App.Tests/TransitionExampleShots.cs` |

순서 안: 클립 → 예시를 한 덩어리로 되돌리고 조립 → 캐릭터에 붙는 연출 → 씬·카메라·깊이·캐릭터 리그(가장 크다) → 코어 사본 줄이기. 하나씩, 각각 테스트 통과 · 커밋.

## 8. 열려 있는 것

1. **움직임의 거리와 화면 비율**(§4의 끝). "왼쪽에서 들어온다"의 −820px이 21:9에서 얼마가 되어야 하는가. 층의 붙는 자리로 풀리는 것(끝에 붙은 층은 그 끝과 함께 움직인다)과 안 풀리는 것(가운데 붙은 층이 화면 밖에서 온다)을 갈라 T3에서 정한다.
2. **머묾이 이어지는지를 어디까지 보나.** 자리·배율·회전·불투명도가 두 표지에서 같으면 된다 — 그림이 프레임마다 바뀌는 층(장 넘기기)은 한 바퀴가 머묾의 길이와 맞아야 한다.
3. **그림의 빈틈**(§5). PNG의 알파를 읽는 값 — 큰 그림이 많으면 느리다. 한 번 읽어 "빈틈없는 사각형인가"만 적어 둔다.
4. **게임 쪽의 약속.** 게임이 전환을 부르는 길(이름으로) · 머묾을 끝내는 신호 · `covered`를 듣는 길 — 이 저장소 밖(런타임)의 일이지만 `transition/1`의 뜻에 적어 둔다(T5).

## 9. 하지 않는 것

- 카메라 · 깊이 · 캐릭터 · 씬 · 클립 · 이모지 — 다른 두 저장소의 일이다.
- 조립(세트가 세트를 품는다).
- 텍스트 · 소리.
- 가림(마스크) · 그라데이션 · 색의 애니메이션 — 필요해지면 그때(지금 예시 다섯은 색 사각형과 그림을 움직여 된다).
